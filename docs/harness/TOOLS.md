# Tools — инструменты FA и контракт ошибок

Слой отвечает за то, **чем агент действует и как инструменты сообщают об ошибках**. Плохой инструмент врёт модели; хороший — возвращает однозначный результат и код выхода.

## Инвентарь

| Инструмент | Назначение | Вход | Выход |
| --- | --- | --- | --- |
| `scripts/verify.mjs` | инварианты проекта | `--json`, `--diff <base>`, `--protected` | exit 0/1/2, JSON |
| `scripts/fa/queue.mjs` | очередь задач | `list`, `json`, `stats` | таблица/JSON |
| `scripts/fa/models.mjs` | реестр моделей и fallback | `FA_MODELS` | порядок, ключи, классификация ошибок |
| `scripts/fa/loop.mjs` | оркестратор запуска | `--once`, `--task`, `--dry-run`, `--preflight` | exit 0/1/2, `run.jsonl` |
| `scripts/fa/metrics.mjs` | разбор событий OpenCode | путь к `.jsonl` | JSON-метрики |
| `scripts/fa/report.mjs` | статус и PR body | `--pr-body`, `--github-summary` | Markdown |
| `scripts/fa/eval.mjs` | замеры качества | `--suite invariants|model` | JSON + таблица |
| `fa-reviewer` | независимый review | diff + acceptance | `VERDICT: PASS|FAIL` |

Встроенные инструменты OpenCode (`read`, `edit`, `glob`, `grep`, `shell`) ограничены правилами в `opencode.jsonc`. Список разрешённых shell-команд для `verify:` — в `scripts/fa/policy.mjs`.

## Контракт ошибок

Единый для всех скриптов:

- `0` — успех, результат в stdout.
- `1` — проверка не прошла; причина в stderr и в JSON `errors`.
- `2` — ошибка конфигурации/окружения (нет Node, нет очереди, битый конфиг).
- `--json` печатает **только** JSON в stdout; человекочитаемое — в stderr.
- Секреты никогда не печатаются: только имена паттернов и `[redacted]`.
- Сообщение об ошибке содержит файл, проверку и что именно ожидалось.

Пример для агента: `verify` вернул `1` → читай `errors[].message`, чини причину, не отключай проверку.

## Правила проектирования

1. **Узкий инструмент.** Один скрипт — одна задача. Никаких «сделай всё» с флагами-режимами.
2. **Детерминизм.** Одинаковый вход → одинаковый выход. Никаких случайных порядков и времени в проверках.
3. **Идемпотентность.** Повторный запуск не меняет состояние, если нечего менять.
4. **Машинный формат.** `--json` для оркестратора, таблица для человека.
5. **Быстрый отказ.** Сначала дешёвые проверки (синтаксис, JSON), потом дорогие (импорт модулей).
6. **Без зависимостей.** Только Node stdlib: инструмент не должен ломаться из-за supply chain.

## Как добавить инструмент

1. Создай `scripts/fa/<name>.mjs` с CLI-гардом `import.meta.url === pathToFileURL(process.argv[1]).href`.
2. Добавь `npm run` алиас в `package.json` (это делает человек, не FA).
3. Опиши контракт в этом файле.
4. Добавь инвариант в `verify.mjs`, если инструмент влияет на проект.
5. Прогони `npm run verify`.

## Почему не MCP

Для текущего масштаба хватает локальных детерминированных скриптов. MCP добавил бы сетевую поверхность и недетерминизм без пользы. Если появится браузерная проверка UI, она войдёт отдельным инструментом с явным контрактом, а не «магическим» сервером.
