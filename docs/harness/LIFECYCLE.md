# Lifecycle — оркестрация и state machine

Слой отвечает за путь **задача → коммит → PR** и за то, что происходит при провале, повторе и остановке.

## Состояния задачи

```text
        ┌──────────┐
        │   todo   │  [ ]
        └────┬─────┘
             │ claim
        ┌────▼─────┐
        │ claimed  │  [~]
        └────┬─────┘
             │ run + verify
      ┌──────┴───────┐
      │              │
  ┌───▼────┐    ┌────▼─────┐
  │  done  │    │  retry   │
  │  [x]   │    │ 1..N     │
  └────────┘    └────┬─────┘
                     │ limit
                ┌────▼─────┐
                │ blocked  │  [!]
                └──────────┘
```

- `todo` — готова к работе; `needs` или невыполненные `depends_on` пропускаются.
- `claimed` — взята текущим запуском; максимум одна.
- `done` — дифф прошёл проверки, коммит в `fa/work`, есть `- done:`.
- `blocked` — лимит попыток, инфра-провал или решение человека; есть `- blocked:` и issue.

Статусы меняет только оркестратор. Агент не редактирует `TASKS.md`.

## Цикл

```text
preflight → ensure branch → ensure PR
  └─ select → claim → opencode run (с fallback моделей) → diff guard → verify
       ├─ pass: mark done → commit → push → PR body → finish
       ├─ fail: revert → attempts+1 → retry | block → finish
       └─ quota: switch model → retry step | finish (задача остаётся [ ])
  └─ report → metrics → artifact
```

Один запуск обрабатывает ровно одну задачу и завершается. Следующий запуск поднимает watchdog через 30 минут. GitHub Actions cache переносит память, rate-limit состояние и до пяти checkpoint-запусков между чистыми runners. После задачи — отдельный коммит и push: работа не теряется при падении раннера.

## Ветка и PR

- Рабочая ветка — `fa/work`, базовая — `main`.
- Прямой push в `main` запрещён правилами агента и git-хуком.
- На каждый запуск — один rolling PR `fa/work → main`. Тело PR обновляется после каждой задачи.
- Если PR смержен, следующий запуск пересоздаёт ветку от `main`. Если PR закрыт без merge — запуск останавливается.
- Перед началом работы `main` вливается в `fa/work`; конфликт → стоп и issue человеку.

## Повторы и эскалация

- Провал проверки: откат рабочего дерева, `attempts + 1`, повтор сразу (до `FA_MAX_ATTEMPTS`).
- Квота/429/401 провайдера: откат частичных правок, переход на следующую модель из `FA_MODELS`, тот же шаг и та же попытка.
- Все модели вернули квоту/недоступность → запуск завершается, задача остаётся `[ ]`; следующий watchdog попробует снова.
- Старые `[!]` с причиной quota/429 автоматически снимаются при старте запуска: квота не является свойством задачи.
- Инфра-провал (нет процесса, таймаут, сеть): не считается попыткой задачи, но считается инфра-провалом запуска.
- 3 инфра-провала подряд → остановка запуска + issue.
- Исчерпаны попытки → `[!]`, открытая issue `FA blocked: Txx` создаётся или обновляется актуальной причиной (старый текст причины заменяется, дубликат не создаётся), запуск завершается.
- Человек разблокирует: меняет `[!]` на `[ ]`, правит acceptance/`needs`, закрывает issue.

## Остановка

- `FA_ENABLED=false` — глобальный выключатель (repo variable).
- `FA_STOP` в корне — аварийный файл-предохранитель.
- `workflow_dispatch` с `mode=stop` — отменяет активные запуски.
- Закрытый PR, пустая очередь, исчерпанный бюджет — штатная остановка.
- Watchdog не поднимает новый запуск, если очередь пуста или включён стоп.

## Почему один запуск = одна задача

Старый «ночник» запускался раз в час, делал одну задачу и уходил; watchdog теперь запускается каждые 30 минут. Один job больше не держит непрерывный цикл: так проще ограничить стоимость и не терять работу при падении раннера. Модели переключаются внутри шага, а не между задачами.

Если одинаковая причина отказа встречается как минимум три раза за 90 дней в двух или более разных задачах, FA создаёт одно GitHub issue-предложение по улучшению harness. Оно дедуплицируется по fingerprint, содержит последние наблюдения и никогда не добавляет задачу в `TASKS.md` автоматически.

## Идемпотентность

- Повторный запуск видит `[x]` и не берёт задачу снова.
- Коммит содержит `FA-Task: Txx`; повторный claim после падения начинается с чистого дерева.
- `fa/work` — единственный источник незавершённой работы; секретов и локальных артефактов в ней нет.
