# Prompts — версионирование и замеры

Промпт — такой же код, как и всё остальное: у него есть версия, владелец, замер и откат. «Кажется, стало лучше» не считается основанием для смены модели или системного промпта.

## Что версионируется

| Компонент | Где живёт | Версия |
| --- | --- | --- |
| Системный промпт агента | `.opencode/agents/fa.md` | `fa-v1` |
| Промпт задачи | `scripts/fa/loop.mjs` → `buildTaskPrompt` | `task-v1` |
| Промпт reviewer | `.opencode/agents/fa-reviewer.md` | `review-v1` |
| Контекст проекта | `AGENTS.md`, `docs/CONVENTIONS.md` | git SHA |
| Модели | `scripts/fa/models.mjs` + `FA_MODELS` | упорядоченная цепочка fallback |

Версия промпта задачи печатается в `run.jsonl` и в `summary.json`. При изменении текста версия увеличивается вручную: `task-v1` → `task-v2`.

## Правила изменения

1. Один PR — одно изменение промпта или модели.
2. Сначала замер на текущей версии, затем на новой.
3. Сравнивать pass rate, число шагов, токены, время и размер диффа.
4. Если новая версия хуже — остаться на старой; если лучше — зафиксировать baseline.
5. Не менять одновременно промпт и модель: иначе непонятно, что дало эффект.

## Замер

### Инварианты (уровень 1)

```bash
npm run verify
```

Быстро, бесплатно, без модели. Это не замер качества, а защита от регрессий.

### Модель (уровень 2)

```bash
npm run fa:eval -- --suite model --models google/gemini-3.1-flash-lite,nvidia/nemotron-3-ultra-550b-a55b
```

Замер задаёт один и тот же детерминированный вопрос по репозиторию, требует JSON-ответ и проверяет его без модели:

- сколько ключей в `STORAGE_KEYS`;
- какие языки есть в `I18N`;
- какие темы перечислены в CSS;
- какие поля обязательны у задачи в `TASKS.md`.

Считаем: корректность ответа, длительность, токены, число шагов. Репозиторий не меняется, поэтому замер безопасен и воспроизводим.

### Baseline

Заполняется после первого прогона на выбранной модели. Пустая таблица — это честное «ещё не мерили», а не выдуманные числа.

| Версия | Модель | Pass | Шаги | Токены | Время |
| --- | --- | --- | --- | --- | --- |
| `fa-v1` / `task-v1` | `nvidia/kimi-k3.1-pro` | — | — | — | — |
| `fa-v1` / `task-v1` | `google/gemini-3.1-flash-lite` | — | — | — | — |

Обновлять при каждом принятом изменении промпта или модели. Значения брать из `fa/eval/<timestamp>.json`.

## Откат

```bash
git revert <commit>
```

Промпт и модель откатываются вместе с коммитом. После отката — повторить замер и убедиться, что метрики вернулись к baseline.

## Анти-паттерны

- «Добавим в промпт ещё 200 строк правил» вместо инварианта в коде.
- «Модель стала лучше» без замера.
- «Промпт победил, но мы поменяли ещё и лимиты» — несравнимый эксперимент.
- «Один удачный запуск» как доказательство.
- Смена модели в пятницу без baseline и без возможности отката.

## Связь с инцидентами

Каждый инцидент заканчивается одним из двух:

1. Инвариант в `scripts/verify.mjs`, если ошибку можно проверить детерминированно.
2. Замер в `eval`, если ошибка вероятностная и требует модели.

Промпт правится только после этого. Иначе инцидент повторится с другой формулировкой.
