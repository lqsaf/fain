# Conventions — fain

Документ описывает, как устроен проект и какие правила обязательны для FA и людей.

## Структура

```text
index.html          лента новостей
settings.html       настройки
css/styles.css      все стили, темы через CSS-переменные
js/data.js          STORAGE_KEYS, I18N, localStorage, загрузка и merge ленты
js/feed.js          рендер карточек, группировка по времени, отметка «прочитано»
js/ui.js            тема, ASCII-волны, верхняя панель
js/main.js          bootstrap страницы ленты
js/settings.js      рендер страницы настроек
worker.js           Cloudflare Worker: RSS → Gemini → KV, отдача ленты
wrangler.toml       конфигурация Worker и KV
```

Без сборщиков, фреймворков и npm-зависимостей. Node нужен только для проверок и FA-оркестратора.

## Данные и localStorage

Все ключи объявлены в `STORAGE_KEYS` (`js/data.js`) и имеют вид `fain_<name>_vN`:

| Ключ | Назначение |
| --- | --- |
| `fain_cached_items_v2` | кэш карточек ленты |
| `fain_read_ids_v1` | карта прочитанных ID (30 дней) |
| `fain_last_updated_v1` | время последней синхронизации |
| `fain_lang_v1` | язык (`ru`, `en`, `zh`) |
| `fain_theme_v1` | тема (`dark`, `light`, `amber`, `phosphor`) |
| `fain_ascii_v1` | боковые ASCII-волны (`on`/`off`) |
| `fain_custom_css_v1` | пользовательский CSS |

Правила:

- Не хардкодить ключи в других файлах — только `STORAGE_KEYS`.
- Новый ключ = новое имя с `_vN`; миграция старых значений обязательна.
- Запись в localStorage всегда в `try/catch` (приватный режим, квоты).
- Кэш ленты и `last_updated` разделяются по языку (задача T07).

## Языки и I18N

`I18N` в `js/data.js` содержит три локали: `ru`, `en`, `zh`.

- Набор ключей во всех локалях одинаковый; пустых строк нет.
- Новые UI-строки добавляются сразу во все три языка.
- `locale` используется для `toLocaleString`/`Intl`.
- Язык определяется из `fain_lang_v1`, затем `navigator.language`, затем `en`.
- Нельзя вставлять русский текст напрямую в JS/HTML, если он виден пользователю.

Инвариант проверяется `npm run verify` (паритет ключей и пустые значения).

## Темы и визуал

- Тема — атрибут `data-theme` на `<html>`, значения: `dark`, `light`, `amber`, `phosphor`.
- Все цвета — CSS-переменные в `css/styles.css`; хардкод цветов в правилах запрещён.
- Тема применяется синхронно в `<head>` до CSS, чтобы не было вспышки (FOUC).
- Верхняя панель скрывается/показывается по скроллу (`js/ui.js`); визуал панели — прозрачный, без blur.
- Масштаб интерфейса — `font-size` на `<html>`; не использовать `zoom`.
- Уважать `prefers-reduced-motion`; анимации не должны блокировать чтение.

## Лента

- `GET` у воркера возвращает `{ items: [...], lastUpdated: "ISO" }`.
- Элемент: `id`, `title`, `summary`, `analysis`, `tag`, `url`, `publishedAt`.
- Сортировка по `publishedAt` убывающая; дубликаты по `id` схлопываются.
- Клиент сначала рисует кэш, затем обновляет его с сервера, затем fallback на `feed.json`.
- «Прочитано» хранится отдельно от кэша и не теряется при смене языка/темы.

## Worker

- Cloudflare Worker, KV binding `FAIN_KV`, cron каждый час.
- `GET /?lang=ru|en|zh` отдаёт ленту; `POST /refresh` запускает генерацию (защищён токеном, задача T15).
- Ключи Gemini читаются только из `env` через `getGeminiKeys(env)`; в коде и логах ключей нет.
- Внешние запросы — с `AbortController` (12–15 с), fallback на следующий ключ/модель.
- HTML из RSS очищается: сначала decode entities, потом удаление тегов (задача T17).
- Ошибка пайплайна не должна отдавать 500, если в KV есть предыдущая лента.

## Код и стиль

- ES-модули, `const`/`let`, без `var`, без глобальных переменных.
- Функции — маленькие, с одной ответственностью; экспорт только нужного.
- Имена — английские; комментарии — по-русски, только там, где неочевидно.
- Никаких `innerHTML` с пользовательскими данными: только `textContent`/`createElement` (кроме статичных статусов).
- Ссылки — `target="_blank"` + `rel="noopener noreferrer"`.
- Никаких новых зависимостей и внешних CDN.

## Проверки

```bash
npm run verify          # инварианты, быстро и бесплатно
npm run verify:json     # машинный формат для оркестратора
```

`verify` проверяет: синтаксис JS, паритет I18N, ключи localStorage, контракт HTML↔JS, CSS, `feed.json`, `opencode.jsonc`, протокол очереди, размеры документов и секреты в диффе. Задача может добавить свою команду в `verify:` — только из allowlist (`node ...`, `npm run ...`).

Изменения, которые нельзя проверить инвариантами (визуал, поведение, смысл текста), проверяет человек в PR или reviewer-сабагент.
