# ADR 0002 — Одна задача за запуск и fallback моделей

- Статус: accepted
- Дата: 2026-11-19
- Владелец: @lqsaf
- Заменяет: [ADR 0001](0001-fa-harness.md) в части lifecycle и выбора модели

## Контекст

Непрерывный цикл внутри одного GitHub Actions job оказался дорогим и хрупким:
запуск мог держать concurrency часами, а квота одной модели останавливала весь шаг.
Модель также была продублирована в workflow, agent-файлах и `config.mjs`.

Нужно:

1. Один запуск — ровно одна задача из `TASKS.md`, затем завершение.
2. Крон каждые 15 минут поднимает следующий запуск.
3. Модели выбираются в одном месте.
4. При квоте/429/401 провайдера FA переключается на следующую модель и продолжает шаг.
5. У каждого провайдера свой ключ.

## Решение

- Ровно одна задача за запуск: `loop.mjs` после первой задачи выходит. `mode=run` и `mode=once`
  эквивалентны, `once` оставлен как совместимый алиас.
- GitHub Actions watchdog — `*/15 * * * *`, job timeout 90 минут.
- Единый реестр моделей — `scripts/fa/models.mjs`. Порядок по умолчанию:
  1. `anthropic/claude-haiku-4-5` — `ANTHROPIC_API_KEY`;
  2. `google/gemini-3.1-flash-lite#low` — `GEMINI_API_KEY`.
  Переопределение — repo variable `FA_MODELS` (тот же формат `provider/model#variant`).
- `--model` передаётся только оркестратором; в `.opencode/agents/*.md` модели нет.
- Ошибки `quota`, `auth`, `unavailable` классифицируются в `models.mjs`.
  При них частичные правки откатываются, запускается следующая модель с тем же
  промптом и той же попыткой. Если модели кончились — запуск завершается, задача
  остаётся `[ ]`, следующий watchdog попробует снова.
- Квота больше не блокирует задачу `[!]` и не ждёт 65 секунд.

## Последствия

Положительные:

- Стоимость одного запуска ограничена одной задачей.
- Concurrency освобождается быстро; следующий запуск стартует по расписанию.
- Смена моделей — одна правка в `models.mjs` или `FA_MODELS`.
- Квота одного провайдера не останавливает работу.

Компромиссы:

- Холодный старт на каждую задачу: контекст не накапливается между задачами.
- Для полного fallback нужны ключи обоих провайдеров; при одном ключе fallback
  вырождается в одну модель.
- Если обе модели исчерпаны, задача ждёт следующего окна квоты.

## Проверки

- `npm run verify` — синтаксис скриптов, реестр моделей, очередь, инварианты.
- `npm run fa:preflight` — показывает цепочку моделей и наличие ключей.
- `npm run fa:eval -- --suite model` — замер качества на обеих моделях.
